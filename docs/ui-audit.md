# UI-аудит и правила единого интерфейса

Ноябрь 2026. Что было не так, какие правила приняты и что уже сделано в коде. Правила на уровне кода —
в [frontend-concept.md](frontend-concept.md#dialogs-settings-column-switches); этот файл объясняет «почему» и хранит
список открытых вопросов.

Проверялось в браузере на живом стеке (1440, 768 и 375 px, светлая и тёмная темы): «Все записи», «Личные»,
«Корзина», проект, запись (расшифровка, саммари), все экраны настроек, публичная ссылка `/s/…`, лендинг, `/ui`.
Экраны входа и приглашения (`/auth`, `/invite/…`) — только по коду (сессия QA не сбрасывалась).

## 1. Что было не так

### Каркас страницы
| Экран | Проблема |
|---|---|
| Запись vs проект vs списки | Три разных каркаса. Запись: своя верхняя полоса 48 px, отступ `px-6`, заголовок `2rem`. Проект и списки: `AppDocumentPage`, отступ `px-10`, заголовок `text-3xl`, верхний отступ `pt-14`. Левый край контента на записи был на ~14 px левее, заголовок — на другой высоте |
| «⋯» и действия | Запись: «Поделиться» и «⋯» в верхней полосе у края окна. Проект: «⋯» в шапке документа у края колонки. Списки: «Загрузить» в тулбаре, а не в шапке. Участники: «⋯» слева от основной кнопки, в проекте — справа |
| Настройки | Третий вид шапки: мелкий заголовок (`text-2xl semibold`), линия-разделитель на всю ширину, шапка не прокручивается. Выглядело как другой продукт рядом с рабочими экранами |
| Профиль, «Общие», «AI и модели» | Колонка 76rem: подпись слева, поле ввода в ~1000 px от неё справа — строка «разъезжается», взгляд не связывает подпись с контролом. Отсюда ощущение, что профиль «плывёт» |
| Отступы в настройках | У каждого view свой `content-class="px-4 pb-10"` (игнорировался) и свой `pt-2`/`pt-4` |

### Контролы
| Где | Проблема |
|---|---|
| Тулбар списка записей | Поиск `md` (34 px), фильтры и «Загрузить» `sm` (26 px) в одной строке |
| Кнопки в шапках настроек | «Новый проект/тег/шаблон», «Пригласить по ссылке» — `sm`; «Новая организация», «Новый пользователь» — `md` и без иконки |
| Кнопка «Создать» у «Токены API» | Вторая основная (залитая) кнопка на странице внутри секции |

### Строка записи
| Проблема | Причина |
|---|---|
| Теги обрезаются («Встре…», «Обмен данны…») | Чипы сжимались (`shrink`, `max-w-28`) в колонке 112/176 px |
| Колонка тегов «скачет» | Выравнивание по правому краю: 1, 2 чипа или 2 + «+N» начинаются в разных точках |
| Проект обрезается и не совпадает по строкам | Колонка 144 px, имя «Лаборатория бизнеса» не помещалось |
| На телефоне теги то в строке с метаданными, то переносятся | `flex-wrap` общей строки: время, проект и чипы вместе |

### Создание сущностей
Теги, проекты, шаблоны, токены — в модалках. Приглашения — формой прямо на странице, результат — карточкой под
формой. Организация и пользователь — отдельной страницей `/new`.

### Мелочи
- Публичная страница `/s/…` и лендинг: нет переключателя темы (у гостя нет меню профиля), нет «скопировать ссылку».
- Хлебная крошка с названием записи в верхней полосе дублировала заголовок сразу под ней.
- Пустое состояние «Приглашений пока нет» — абзац текста, а не общий `AppResultState`.

## 2. Правила (система)

**Каркас.** Один каркас на все экраны. Константы в `shared/ui/app/pageContainer.ts`:
боковой отступ `px-4 md:px-10`, верхний `pt-6 md:pt-10`, один h1 (`text-2xl md:text-3xl bold`).
- Рабочие страницы (`AppDocumentPage`, колонка `--page-width` 76rem): строка-лид (иконка или «← назад» слева,
  действия справа) → заголовок → бейджи → описание → контент.
- Настройки (`AppPage` в контейнере, колонка `--page-width-narrow` 50rem): заголовок и описание слева, действия
  справа, прокручивается вместе с контентом, без линии-разделителя.

**Почему настройки у́же.** Недавнее решение «одна ширина 76rem везде» хорошо для списков записей (нужны колонки), но
в настройках почти всё — строка «подпись ↔ контрол». При 76rem между ними метр пустоты. 50rem держит их в одном
поле зрения; таблицы настроек (2–3 колонки) в эту ширину тоже помещаются. Ширина — один токен, поменять легко.

**Действия страницы** — всегда в шапке, справа вверху колонки контента. Порядок: основное действие (`md`, с иконкой)
→ второстепенные (`outline`/`ghost`) → «⋯» последним. В тулбарах — только поиск и фильтры.

**Высоты контролов.** В одной строке — одна высота. Тулбар страницы: всё `md` (34 px; на телефоне 44 px).
`sm` (26 px) — только внутри строк списков и в шапках секций. `xs` — внутри чипов и плотных таблиц.

**Строка списка записей.** Широкий список — фиксированные колонки с выравниванием влево:
иконка · название + статус (тянется) · теги 13rem · проект 10rem (от `@5xl`) · длительность · автор · время.
Узкий: название → строка метаданных (статус · время · длительность · проект) → строка чипов.

**Чипы.** В плотных строках — только целые чипы: сколько помещается в бюджет ширины, остальное «+N» (полный список
в подсказке). Считается по длине текста (`fitTagChips`), без измерения DOM — одинаково на сервере и клиенте.
Чип обрезается только когда он один и длиннее всей колонки.

**Создание — всегда модалка.** Кнопка в шапке страницы → `AppModal` с формой → «Отмена» / основное действие.
Если результат показывается один раз (ссылка-приглашение, токен) — он остаётся в той же модалке вторым шагом.

**Пустые состояния** — `AppResultState` (иконка, заголовок, текст, действие), не абзац текста.

**Типографика.** h1 страницы `text-2xl md:text-3xl bold`; заголовок секции `text-base semibold`; подпись строки
`text-sm medium`; описание страницы `text-base muted`; описания строк и метаданные `text-sm`/`text-xs muted`.

## 4. Не сделано / на решение владельца

- **Ширина настроек 50rem** вместо общей 76rem — отступление от недавнего решения, причина выше. Вернуть: одна
  строка в `layouts/settings.vue`.
- **Действия записи больше не «прилипают»** при прокрутке длинной расшифровки (раньше была фиксированная полоса).
  Плеер внизу остаётся. Если нужно — сделать лид-строку `sticky`.
- **Заголовки колонок** в списке записей (Теги / Проект / Длительность) не добавлялись: колонки читаются и без них.
- **Экраны `/auth`, `/invite/…`, `/oauth/authorize`, `/home/setup`** визуально не пересматривались.
- **Страницы-детали** «Организация» и «Пользователь» (`AppDetailTemplate`) остались как были: редактирование на
  отдельной странице, создание — в модалке.
- Идеи на потом: сохранённые фильтры списка; сортировка списка записей; плотность строк (компактно/просторно);
  скачивание `.txt`/`.md` с публичной страницы; аватар пользователя (сейчас только инициалы) — нужна миграция.

## 5. QA pass 2 (ноябрь 2026)

Второй независимый проход: все экраны заново в браузере (1440 / 1024 / 768 / 375, светлая и тёмная), плюс новые
требования владельца. Разделы 2–4 выше описывают состояние после первого прохода; где они расходятся с этим
разделом — прав этот.

### Что изменилось в системе

| Правило | Было | Стало |
|---|---|---|
| Ширина | `--page-width` 76rem, настройки 50rem | **Одна ширина 63rem** для списков, проекта, записи, настроек и `/s/…`. `--page-width-narrow` удалён. Длинный текст (расшифровка, саммари) — расшифровка, саммари и история на всю ширину колонки (63rem) |
| Действия рабочих страниц | В шапке колонки | **Верхняя полоса на всю ширину** (как в Notion): слева «где вы» / «← назад › название», справа действия — все `ghost` («Загрузить», «Поделиться», «⋯»). Не прокручивается. В настройках действия остались в шапке страницы |
| Скрытая боковая панель | Своя полоса `AppLayout` + полоса страницы | Одна полоса: кнопка «Показать боковую панель» в полосе страницы |
| Тема по умолчанию | Палитра «фиолетовая» | **Системная тема + нейтральная палитра** для нового посетителя (в том числе лендинг, `/auth`, `/s/…`). Cookie палитры пишется только после явного выбора |
| Селекты | Выбранный фильтр — акцентная рамка и заливка; открытый — другая рамка | Рамка и фон не меняются никогда; плейсхолдер приглушённый, значение — основным цветом |
| Вкладки записи | Сегмент со смещением влево | Сегмент `AppTabs` (по решению владельца), ровно по краю контента |
| Свойства записи | «Ещё» / «Все свойства» | Все свойства сразу |
| Саммари | Карточки с рамкой, «Создать саммари» с рамкой рядом с подсказкой | Без рамок: заголовок, строка «дата · модель», действия справа, текст 15px/28px в колонке чтения; «Создать саммари» — `ghost` над списком, в пустом состоянии — основная кнопка |
| Расшифровка | На всю ширину колонки | Колонка чтения, счётчик слов и «Копировать» над текстом |
| Плеер | Отступы внутри колонки — уже контента | Отступ страницы снаружи колонки: края совпадают с контентом до пикселя (проверено на 1440 / 1024 / 768 / 375) |

### «Клик не срабатывает, контент дёргается» — причины

1. **Строка записи.** Чекбокс 18 px лежал поверх ссылки на всю строку: промах на пару пикселей открывал запись.
   Теперь вся левая зона строки (36 px, 40 px на телефоне) отмечает запись.
2. **Панель «Выбрано: N»** заменяла тулбар другой высоты — список прыгал под курсором (на узких экранах на ~40 px).
   Теперь панель лежит поверх тулбара, высота не меняется.
3. **Гонка оптимистичных PATCH** (теги записи, модели в «AI и модели»): ответ на первый запрос затирал вторую,
   ещё не сохранённую отметку — галочка пропадала и появлялась. Запросы одной сущности идут по очереди, состояние
   с сервера применяется только после последнего.
4. **`AppSelect`**: при каждом открытии и вводе в поиск список очищался до спиннера и возвращался (высота прыгала),
   а пока шёл поиск, варианты были `disabled` — клик терялся. Варианты остаются на экране до прихода новых.
   Мультивыбор: чипы переносились и растили триггер — открытый список уезжал. Теперь одна строка: два чипа и «+N»
   (в «AI и модели» выбранные модели — списком под селектом).

### Ещё исправлено

- `/s/…`: колонка и отступы как в приложении (было 42rem); переключатель темы проверен (сохраняется в cookie).
- `/auth`, `/invite/…`, `/oauth/authorize`, страница ошибки: добавлен переключатель темы.
- Свойства записи на телефоне: «Длительность» и дата больше не обрезаются.
- Приглашения на телефоне: срок действия переносится, а не обрезается.

### Осталось

- **Поиск ищет только целые слова** (`plainto_tsquery`, конфигурация `simple`): по «созв» ничего, по «созвон» —
  находит. Для поиска по мере ввода нужен префиксный запрос на бэкенде.
- **Cookie `palette=violet` у старых посетителей.** Раньше значение по умолчанию записывалось в cookie само, отличить
  его от явного выбора нельзя: у таких браузеров останется фиолетовая, пока не выбрать «Нейтральная» в меню профиля.
- **Две полосы на телефоне**: навигация приложения (меню, организация, поиск) и полоса страницы. Объединять —
  отдельная задача (телепорт в шапку `AppLayout`).
- Панель «Выбрано: N» на телефоне закрывает только первую строку тулбара; под ней остаётся пустая строка фильтров.
- Таблица «Пользователи» на 375 px шире экрана и прокручивается вбок.
- Высота контролов в модалках на телефоне 34 px (в остальных местах 44 px).
- `AppResultState` рендерит заголовок как `h1` — на странице с собственным `h1` их становится два.
- В локальной базе QA аудио записей нет в хранилище: плеер на `/s/…` показывает «Аудио недоступно».
